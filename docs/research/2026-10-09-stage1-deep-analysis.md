# MuSlate 修复版 E1 深入分析与下一轮实验建议

2026-10-09。本轮进一步检查报告、评估与搜索代码，并重放公共前缀测试中的18,000次执行动作，补充奖励构成及基线差异分析。新增分析均为事后探索，不修改原冻结协议，不新增确认性成功判据；下述下一轮配置是建议，尚未实施。

主要判断：合法逐项监督的有效性已有可信证据。下一步应优先区分列表内组合优化、跨时间规划及搜索剪枝限制，再决定新模型与Adaptive-H的实现重点。

依据：[第一阶段正式报告](D:/Coding/next_codex/docs/research/2026-10-09-stage1-results.md)、[补充分析JSON](D:/Coding/next_codex/results/e1_stage1_20261009/detailed_behavior_analysis.json)、[分析脚本](D:/Coding/next_codex/ops/analyze_stage1_behavior.py)。补充JSON绑定原统计文件与分析脚本SHA；每一步重新计算奖励，并核对分项折扣和等于原始returns减公共前缀。

## 一、可以相信哪些结论

第一阶段修复了已发现的非法动作、超剩余时域、标量/批量奖励不一致以及结果一致性问题。主比较在查看test之前定义，权重由21个新validation选择；各5seed的最终模型和新test也均已齐备。这使E1能够承担论文的受控监督可行性证据。

主比较L1−L0的sid_hier回报差为4.2197 [3.7823,4.5999]；每seed分别为4.2670、4.4571、3.4520、4.7195、4.2031。结果不由单个seed的异常高收益造成。完整episode同项为5.6180 [4.8922,6.2544]，方向一致。

但是，117,600次决策是核验记录数量，不是117,600个独立统计样本。独立训练复制仍只有5个；目录固定，测试沿用同一用户群，闭环reward噪声关闭。当前结论只适用于这一受控环境，仍需跨目录、用户和反馈机制检验。

L1的日志分布一步reward MAE由.2855降到.1305，约降低54.3%；flat_uniform也因L1监督得到3.4237的主协议回报提升。因此收益并非专属于SID。item_scores与reward共享unary参数，L0并不是一个完全未训练的打分头；辅助监督改变了共享表示和预测，而不仅是提供一个更好的候选排序器。

U1是同一类学习模型接受全物品真值标签的特权参考，不能混同真实环境Oracle。U1−L1的sid_hier区间跨零，既不能证明两者等效，也不能据此判断模型误差已经解决。

## 二、新增的奖励分解

模拟器单步奖励可以精确拆成：兴趣匹配贡献 − 饱和扣分 − 列表相似性扣分。下表对公共前缀之后的15步按原gamma折扣累加，再计算配对条件的均值差。正值表示该分项提高回报，负值表示降低回报。

| 比较 | 兴趣匹配贡献差 | 饱和项贡献差 | 列表相似性项贡献差 | 总回报差 |
|---|---:|---:|---:|---:|
| L1 hier − L0 hier | +2.429 | +3.283 | −1.492 | +4.220 |
| L1 hier − L1 sid_flat | −3.669 | +0.116 | +4.114 | +0.561 |
| L1 hier − L1 flat_uniform | +2.048 | +0.205 | −1.475 | +0.778 |

![公共前缀实际轨迹奖励构成](D:/Coding/next_codex/results/e1_stage1_20261009/figures/stage1_reward_decomposition.png)

对L1−L0，收益在实际轨迹上表现为更高兴趣匹配及更少饱和扣分，但列表相似性项变差。可以推断辅助监督改善了决策所需的部分信息，同时没有消除列表组合优化的需求；不能将这种回报构成直接解释成对reward/dynamics模块的因果归因。

对sid_hier−sid_flat，净收益来自明显的相似性扣分下降，代价是兴趣匹配贡献下降。这使“局部细化改善列表内搭配”成为优先验证的解释。当前结果还不能说明这些改变由更长的规划时域造成，因为两个方法都用了同样的depth=2，执行路径及后续状态也会随动作变化。

对sid_hier−flat_uniform，层次方法的实际轨迹得到更高兴趣匹配，却支付了更多列表相似性扣分。因此也不能简单写成“层次搜索在所有基线上都通过更多样化获益”。

相似性项基于item embedding内积，可以为负；负的扣分意味着奖励增加。因此它是连续向量相似性目标，不是类别去重数量，也不是始终非负的惩罚。论文应明确这一奖励定义。

## 三、为什么现有扁平基线还不够

公共前缀L1中，flat_policy−flat_uniform=-1.7166，事后配对区间[-2.1075,-1.3860]，五seed均为负；L0和U1也同方向。这个现象不能只归因于L0评分较差。

代码显示flat_policy以unary top-K为固定锚点，每个候选只随机替换一个位置，另外四个位置保留。因此它没有执行多轮坐标优化，也不能在一个候选里同时修正多个互相冲突的位置。

实际执行列表的平均粗类别数（K=5）为：

| L1方法 | 不同粗类别数/列表 | 每步相似性扣分均值 |
|---|---:|---:|
| reactive | 1.993 | 2.044 |
| flat_policy | 3.071 | 0.696 |
| flat_uniform | 4.653 | −0.057 |
| sid_flat | 4.661 | 0.627 |
| sid_hier | 4.683 | 0.127 |

这些数据支持候选局部性和列表组合冲突是值得追查的因素。sid_flat与sid_hier粗类别覆盖几乎相同，相似性扣分却差很多，说明仅统计类别数无法解释细化收益；需要直接检查item之间的相似性及fine选择。

下一轮需要flat_coordinate_refine，并以随机等规模分组、真实分组进行对照。当前模拟器按真实coarse类别生成item embedding与饱和状态，SID也使用这套类别结构。这是合法但有利的结构先验，不能直接外推到真实数据中有噪声的学习分组。

## 四、深规划实验必须额外控制的两个问题

### 1. 即时奖励剪枝可能挡住长期动作

Lookahead.plan和_value都先按当前即时奖励排序，只对前beam_width个候选递归。E1的beam_width=3。意味着长期价值高、但当前奖励排名第4及以后的动作，会在未来价值被评价之前排除。

这是一项搜索近似，不是本轮新发现的非法行为。它会限制“加深是否有效”的解释：失败可能来自模型误差，也可能来自短视剪枝。增加候选池大小不能自动解决这个问题。

建议在固定状态诊断中比较beam={3,8,16}；小环境用穷举Oracle。记录参考长期好动作的即时奖励名次及被剪枝比例。在200-item环境中若只计算了近似参考值，应称为“参考候选/搜索范围内最佳”，不能声称全局最优。

### 2. 相同随机种子不保证相同根候选

当前proposal持有连续使用的RNG，递归层也消耗同一随机流。改变depth后，后续决策的根提案可能改变。只把seed设成同一个数，并不能使深度比较拥有相同候选池。

固定状态诊断应直接缓存并复用根候选池，或者给根提案及每个树节点分配独立、可复现的随机流。闭环实验只能配对相同初始条件和前缀；不同策略访问状态不同，不应声称整个闭环过程始终有相同状态/候选。

这些问题应在下一轮协议及测试中处理，原E1冻结产物保留。

## 五、成本结果支持什么

L1公共前缀的sid_hier约241.1ms，sid_flat319.6ms，flat_policy141.6ms，flat_uniform41.9ms。sid_hier在当前实现中相对sid_flat得到更高平均回报且更低延迟，但相对flat_uniform需约5.75倍延迟换取.7784回报。

下一轮应比较整条回报—成本曲线，不只比较B512上的一个点。操作估计与墙钟延迟分别报告；小batch固定调用开销必须计入新校准。延迟增加p50/p95和串行GPU复测，部署总开销还需计入belief编码。所谓等预算，应明确是同一估计操作上限，不要写成精确相同墙钟。

当前辅助权重按sid_hier验证选择。因此E1方法间比较是“在该选定模型上的比较”，并不等于各基线都经过同等充分的独立调参。后续正式算法比较要给予各方法相同验证资源，所有选择在test之前冻结。

## 六、下一轮最先做什么

建议下一轮命名为“R2-A：完整一步规划、深度与剪枝诊断”。先复用现有模型，任务目标是回答是否值得增加规划深度，并定位阻碍。

| 项目 | 建议设置 |
|---|---|
| 学习模型 | 现有L0/L1各5训练seed，共10checkpoint；先固定当前权重，解释为这些模型上的条件性深度效应 |
| Proposal | flat_uniform、sid_hier |
| 深度 | depth=0/1/2/3，分别包含1/2/3/4个动作；始终受剩余时域截断 |
| 一步基线 | 同一proposal + 完整reward（含pairwise）的depth=0；reactive只作额外参考 |
| 主协议 | 共享5步行为前缀；完整episode作为辅助稳健性比较 |
| 第一组诊断 | 固定观察历史/状态、缓存根候选，比较不同depth；真值只用于评价 |
| 第二组诊断 | 固定状态下beam=3/8/16；小环境穷举Oracle核对 |
| 闭环实验 | 10模型×2proposal×4depth=80配置/评估协议；其中训练seed已包含在10模型中 |
| 轨迹数量 | 探索先保持原16用户以便衔接；最终确认扩大到全部64个既有用户，并加入多条独立初始轨迹；不称为新用户泛化 |
| 计算比较 | 固定提案设置的深度曲线 + 三档总估计预算下的回报/实测延迟曲线；档位通过校准预实验确定，在test前冻结 |
| 随机性 | 独立的新验证/最终测试轨迹池；按用户和训练seed配对；记录根提案与递归随机流身份 |

应输出四份主要结果：

1. depth相对0的配对回报差及95%区间，列出每seed结果；不能用reactive代替完整一步目标。
2. 每个depth的reward/value预测误差、所选动作高估，以及固定probe-action上的open-loop/re-encoded belief差异。
3. beam宽度与候选剪枝诊断，区分未来收益不足、搜索排除好动作和模型错估。
4. 回报—总操作成本—实测延迟曲线；硬预算失败/未完成也计入，不能只报告成功完成样本。

1/3/5步预测诊断可以独立于planner depth设置执行。所选动作高估应对同一明确动作序列或后续策略计算预测与真实回报；不能拿预测的open-loop最优值减去另一套闭环执行策略回报后直接称为模型误差。

真实环境Oracle利用隐藏状态，和learned模型的差距还包含信息优势，不能全部归于动力学拟合。小环境Oracle主要判断环境是否提供长期机会，并排除搜索近似；机制干预应保持信息条件明确。

## 七、结果决定后续投入

| R2-A观察 | 接下来优先做什么 |
|---|---|
| learned深度>0在可比成本下稳定胜过depth=0 | 检查收益的状态异质性和可预测性，准备Adaptive-H |
| 小环境Oracle有收益、beam增大后恢复，而beam=3没有 | 优先改善搜索剪枝/候选覆盖，再评价模型 |
| Oracle有收益、搜索充分后learned仍无收益 | 做L0/L1-A/L1-B/L1-C反馈历史对照及多步一致性诊断 |
| 在所测机制的小环境Oracle中也无实用深度收益 | 调整长期机制/任务范围，降低对跨时间规划的贡献主张 |
| 层次优势在depth=0就已存在，flat_coordinate_refine也能达到 | 将重点转向列表组合优化；继续检验分组是否提供独立价值 |
| 只有少数状态值得加深，合法信号能预测这些状态 | 再实施逐层扩展的Adaptive-H，与验证选出的最佳固定配置比较 |

若扩展饱和/偏好漂移2×2环境，先运行Oracle机制实验。旧learned checkpoint跨环境直接测试应明确标为分布外迁移；不能混入同分布的纯机制比较而不说明训练分布变化。

随后再推进反馈历史四组模型、flat_coordinate_refine与随机分组、ensemble修复及Adaptive-H。大规模MCTS/Transformer升级目前没有直接证据优先级。

## 八、KuaiRand与论文写作可以同步做的工作

KuaiRand先完成流式数据质量、时间拆分、反馈语义、特征可用时间、会话假设与逐项预测基线。未发现原生slate/position字段时，不将连续交互直接拼成同时曝光列表。真实反馈结果与合成闭环机制证据分开报告；learned simulator中的回报提升不能单独证明真实策略有效。

论文现在可以起草问题定义、合法监督条件、有限时域动作合同、E1实验设计、修复后的监督可行性结果及其局限。深规划机制、SID独立贡献和Adaptive-H优越性仍应等待对应实验。回报为负，效应优先用绝对回报差；不要用容易误导的负分母百分比提升。

完整episode与公共前缀回报也不宜直接相减来解释冷热启动：前者自主选择前5步，后者固定行为前缀，起始条件之后的动作与状态分布不同。应比较各协议内部的配对效应。

最先交付R2-A的深度与剪枝结果，再据其决定训练改动，是当前成本较低、对论文方向信息量较高的一步。
