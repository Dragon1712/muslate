## 3. 第一优先：R3-A 起点来源 × 允许替换邻域

目标是回答“真实 SID 提供好起点，还是组内细化限制了有用替换”，先不重训模型、不改变环境。固定现有 L1 五训练 seed、16 用户与共享五步行为前缀，使用新探索轨迹命名空间。可提议 33M 区域作为 R3-A 候选，但须在协议冻结前查已有训练、校准及探索种子登记；本文不声称它已被证明无碰撞。40M 区域继续保留给最终确认，不能用于选方法或阈值。

每个模型/状态有五个具体起点来源：uniform、真实 SID、随机分组 271/811/1459；有五个具体替换邻域：全目录、真实 SID 组内、上述三个随机分组组内。每来源生成 32 个合法起点，按同一预测即时 reward 规则取最好 4 个，并列按保存索引处理。**同一起点来源的五邻域逐字节复用相同候选池、top4 与初始分数；不同来源保持各自生成机制。**随机来源与随机邻域包含全部九种配对，不只比较同一分组。

中预算内部矩阵为 25 cells/seed × 5 seed＝125 个 seed 级配置，乘 16 状态＝2,000 个状态配置；这不是 125 个独立训练重复。报告汇总为 3×3 概念因素，随机分组先在训练 seed 内平均。机制实验只细化固定状态，不把该规模称为闭环 episode 数。

各邻域得到相同的**额外细化估计预算**，初始化构造和评分成本另计。保存提议/合法/新颖候选数、跨组可达性、重复与缓存命中、reward 调用与样本数、选择偏差、预测改善和 evaluator 真值改善。真值只能在候选与模型选择冻结后评分，不参与生成或接受细化。

主对比预定为“真实 SID 起点下，全目录−真实组内细化”的即时真实奖励改善。建议实用门槛暂定 **+0.05 即时 reward 单位**，正式冻结前先根据既有奖励尺度确定；它是计划中的工程价值建议，不是已经达到的结果，也不是显著性门槛。主统计先按用户配对平均，再对五训练 seed 计算 df=4 的配对 t 95% CI；其他来源交互与覆盖诊断为探索性，不能挑较有利区间作主结论。

若方向稳定且达到预定价值门槛，才选择一个混合方案，例如 SID 起点＋全目录细化，进入闭环验证。与无分组细化及原真实 SID 层次，在低/中/高三个**包含初始化的总估计预算**下比较；建议预定比例 0.5/1/2，中预算由新校准决定，低预算必须能支付共同初始化。若主区间跨零，结论为机制未明确；不通过增加用户或追加随机种子把它补成阳性。

## 4. 第二优先：R3-B 实际候选上的误差与深度机会

R2-C 均匀固定序列 bank 有助于预测诊断，但不是 planner 的实际选择分布。R3-B 从强一步基线与有限深度 planner 实际访问的状态采集候选，按状态来源分别报告；不要用单一策略访问状态替其他策略作全域结论。候选序列、生成策略、模型分数、预算和状态身份先保存并冻结，再由 simulator 离线重放真值。

建议初始范围仍为五既有训练 seed、每策略 16 用户，在 episode20 中固定零基决策时刻 t=5/10/15；两个状态来源暂定为强一步策略及 H=5 固定深度策略，各自闭环访问，共最多 480 个模型关联状态记录。计划 horizon 1/3/5，始终按剩余动作数截断；实际 bank 规模通过无真值 smoke 检查内存和候选覆盖后一次冻结，建议每状态每 horizon 最多 128 条合法序列。若按上限执行即最多 1,440 个状态-horizon bank、184,320 条序列；这仅是存储规模提案，不是已产生的数据，也不增加训练独立复制。新轨迹区间须单独登记，不能沿用 40M。

第一层在**同一状态、同一 horizon、同一候选 bank**内计算选择 regret：bank 内最高真实序列回报减模型所选序列的真实回报，同时报告 top 候选排序、选中序列过估计和生成器覆盖。不同长度的回报不能直接相减解释深度收益；bank 内真值最好序列只是有限候选参考，不是全目录 Oracle，也不是能逐步接收反馈的最优闭环策略。

第二层比较根动作的实际机会：各深度所选第一动作，以及 bank 内全部不同根动作，都接同一个预声明、可部署的续接策略，评价直到同一真实 episode20 终点；奖励沿用原 episode 的全局 `gamma**t`，不是在每个诊断状态重新从 `gamma**0` 计。强一步续接策略在验证阶段选定并冻结，全部根动作共享同一 evaluator 随机性规则。候选内参考根动作由这一共同续接后的真实回报最大者定义，仅用于评价，不给 learned planner 选动作。主机会指标是“候选内参考根动作−强一步根动作”，先在每训练 seed 内对固定时刻/用户平均，建议价值门槛暂定 **+0.20 episode 回报单位**，与总预算约束共同冻结；不能把它与 R3-A 的即时 +0.05 混用。若改为仅评价五步截断，必须另定并标明“五步 return”门槛，不能沿用 +0.20 episode 门槛。

若候选内参考也无实际收益，暂停模型扩张与 Adaptive-H；若参考有收益但模型选错，才进入模型消融；若同 bank regret 很低而不同生成器机会差异大，先修候选覆盖。只有统一续接评价和实际闭环回报才能支持“值得进一步研究深规划”，不能用 MAE 降低代替。

## 5. 条件模型阶段：历史逐项反馈 × 已曝光辅助监督

仅在 R3-B 找到可恢复的决策机会后启动。现有 GRU 已输入历史 slate 与**总 reward**；新增因素是截至当前时刻的**历史逐项反馈**，不是重新命名总 reward，也不是把当前或未来逐项反馈泄漏到预测输入。另一因素是训练时已曝光 item 的辅助监督损失，未曝光 item 不能当作零反馈。

| 计划臂 | 历史逐项反馈输入 | 已曝光逐项辅助监督 |
|---|---|---|
| L0 | 无 | 无 |
| L1A | 无 | 有 |
| L1B | 有 | 无 |
| L1C | 有 | 有 |

这四臂需以新五组配对训练 seed 重训，共 20 模型；现有 L0/L1 只作历史参考，不能直接充当新架构匹配对照。保持日志、训练步数、优化器、reward 结构、容量与可观测信息规则一致；对无反馈臂使用相同接口和屏蔽规则，披露新增参数与计算。权重只在训练/验证上按预声明范围确定，不能按测试闭环回报选参。

主比较建议为 L1C−L1A 的可部署闭环回报，检验已有辅助监督条件下历史逐项反馈的增量；辅助监督主效应和交互为预声明次要项。TF 继续只是诊断。若要归因 transition，另做**冻结 encoder 与 reward head、只改 transition 训练目标**的受控实验，保持 latent 坐标和评价集固定；不自动再增加一个完整 dynamics 2×2。全模型联合重训不能声称 transition 的独立贡献。特权 U1 可作为明确标注的参考上界，不能混入合法输入主方法，也不自动纳入主预算。

## 6. 深度机会仍未明确时的机制分支

优先检查 simulator 中饱和与偏好漂移是否真的创造可以利用的未来机会，再调大模型。建议分别开/关 saturation 与 preference drift，形成四种环境模式；即时 unary/pairwise 项、动作合法性与其他条件固定。先在可穷举的小环境证明有限 horizon 的 Oracle 机会，再扩到原目录的受限候选参考。Oracle 真状态/动力学只进 evaluator 或特权诊断，不能进入 learned planner。

此分支的作用是区分“环境缺少延迟机会”“候选覆盖不足”和“模型选择失误”。若小环境 Oracle 也无超过工程门槛的深度增益，应收缩多步主张；若有机会，再按模式重训匹配模型，不把旧 checkpoint 在改变后的环境中的失配当作方法固有结论。穷举规模、目录与 horizon 必须通过 smoke 后冻结；有限搜索参考不能冒称全局 Oracle。

## 7. 确认与真实数据：分别守住外推边界

最终只确认一个在探索验证中固定的方案。根据既有 pilot 配对方差和 +0.20 回报门槛，确认前选择固定 **10～20 组全新训练 seed**及分析方案；若 20 组仍不足以获得目标精度，应调整结论和预算，不能执行“先看十组，不显著再加十组”。40M 确认轨迹从选参中隔离；不因途中显著而提前停止，不因不显著而追加样本。区分既有用户的新轨迹与 held-out 新用户，两者分别报告。

跨目录需要每个新 catalog 重训匹配臂，或预先设计能处理新 item 特征的泛化编码器；不能把固定 200-item ID embedding checkpoint 直接套到新 ID/目录后称作跨目录泛化。新目录 seed、训练/验证/测试分割与任何映射都在测试前冻结。

KuaiRand-27K 可与 R3-A/B 部分并行，但先做全量内容 hash、行数、缺失、重复、ID 覆盖、时间顺序、随机/标准日志差异、反馈分布与特征 join 审计，并核查特征生成时间和未来泄漏。当前只有 inventory，不能写成全量审计完成。

随后冻结按时间的训练/验证/测试划分、用户纳入规则、reward 定义、session 与负例规则；先做单视频反馈预测、排序、校准，再评价历史逐项反馈与多步预测。未曝光并非负反馈，held-out 测试不能用于选损失权重。当前表头没有原生 slate、位置、候选集合或可核验曝光倾向；不能把相邻视频拼接成“真实曝光 slate”，不能把评分或预测 held-out 表现称为真实闭环策略收益，也不能在缺少倾向与支持条件时声称无偏 slate OPE。任何合成 slate 或模拟器必须另列假设。

Adaptive-H 最后才考虑：须先证明真实未来机会、模型能够恢复其决策收益，再与验证集选出的最佳固定 horizon 在相同预算规则下比较。阈值只在验证区间选，确认时固定；若门槛未满足，继续报告一步强基线和适用边界，不为保留模块强行训练自适应器。

## 8. 预算、复核与时间安排

B 的 6.735276 ms 是旧机器条件下的**估计账本 cap**，实际 mean 延迟约 7.20～8.54 ms，不是墙钟硬上限。新阶段应在受控资源下重新校准 reward batch、score、候选构造、排序、检查和 encoding，保存原始时序及拟合残差；不能把旧系数移植后宣称等真实延迟。机制细化预算与端到端总预算分别建账。若后续要求真实延迟硬约束，应预注册同步计时、超时返回规则与硬件条件，单独比较，不与估计 cap 结果混称。

每阶段冻结完整矩阵、主对比、种子、缺失/失败处理、并列规则与推进门槛。实现后先测试再独立 review，再提交 source 并按 commit archive 部署；保存 Git blob/archive/checkpoint/data/protocol/bank SHA、实际命令与 runtime、预期 cell、退出码、全部 raw 与失败日志。完整重放必须验证动作合法性、状态/历史、chronology、折扣、选择 index、统计聚合与输入变化拒绝；最后生成与审计绑定的结果报告。本地取回再核验 hash；ignored results 须另行备份，不能只依赖 Git。模型代理的启动账本区分请求、接受与实际运行元数据，未知计量为 null，不凭发起设置断言运行身份或 token 用量。

| 优先级/阶段 | 建议顺序与日历范围 | 主产物 | 未达门槛时分支 |
|---|---|---|---|
| P0：R3-A 中预算 | 第1周，2～4工作日 | 125 seed 配置、2,000 状态配置、来源/邻域机制报告 | 区间不明确则保留结论；不直接扩大预算网格 |
| P0：R3-B | 第1～2周，2～4工作日 | 实际候选 bank、regret、统一续接机会报告 | 无机会转小环境机制；覆盖不足先改生成器 |
| P1：27K 审计与预测基线 | 第1～2周，4～7工作日，可部分并行 | 全量审计、时间分割、可观测单视频基线 | 数据/时间不可靠先修数据，不作策略收益结论 |
| 条件：20模型 factorial/transition 对照 | 机会门槛通过后 | 信息×监督主效应、可部署回报、模块受控证据 | 无决策恢复则停止模型扩张 |
| 条件：独立确认 | 方法及固定样本量冻结后 | 新 seed/轨迹/目录确认和范围限制 | 完整报告阴性/不确定结果，不按显著性续样 |
| 最后：Adaptive-H | 上述门槛满足后 | 对最佳固定 horizon 的等预算确认 | 缺少稳定增益则保留固定一步/深度 |

两周执行示例从下一工作日 **2026-10-12** 起算：10月12日冻结 R3-A 协议、种子登记、主对比与数据审计表；13日实现、测试和无真值 smoke；14日 review、archive、校准及 R3-A 完整运行；15日重放、统计与 gate 判断；16日冻结 R3-B 候选/续接协议并启动采集。第二周19～20日完成 R3-B 真值重放和决策机会分解，21日形成推进/停止结论与模型 factorial 冻结草案，22～23日交付 27K 审计及首个预测基线；只有科学 gate 通过才安排模型训练 smoke，不保证两周内完成全部训练和确认。

这些是有可用资源、无需额外数据许可时的粗略日历估计，不是测得 GPU 小时或完成承诺；条件训练与确认可能额外需要 1～2 周，应由 smoke 的实际吞吐与排队情况更新。校准和延迟评价串行、避免 CPU 重放争用；吞吐任务可按 seed 分卡，但保留同步时序与硬件标签。正式启动前重新检查可用 GPU，不沿用本轮占用快照，不触碰无关作业。总体目标是 CCF B，原先安排在 5～6 个月内完成，允许证据充分时提前完成；尚未指定具体会议或硬截稿日，本轮按科学门槛尽早推进，不编造会议截止日期。

首个应交付的是 R3-A 冻结协议和可审阅矩阵，其次是 R3-B 决策机会证据；增加模型、真实数据策略或 Adaptive-H 必须依赖前一阶段结果。本文的安排不会被当作这些实验已经完成的证据。
